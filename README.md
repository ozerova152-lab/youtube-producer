# AI-продюсер YouTube-канала

Набор инструкций, шаблонов и небольшой скрипт сбора данных. Вы открываете папку проекта в ИИ-агенте, который читает `AGENTS.md`, и пишете: «Прочитай AGENTS.md и запусти месяц». Дальше агент ведёт вас по шагам, а решаете и публикуете всегда вы.

Адрес репозитория: `https://github.com/ozerova152-lab/youtube-producer`. Страница-витрина: <https://ozerova152-lab.github.io/youtube-producer/>.

## Что это и что вы получите

За один «месяц» работы проект даёт вам файлы, которые лежат у вас на компьютере в `data/<канал>/runs/<месяц>_<сегмент>_v<N>/`:

- **Залётные видео вашей ниши за 30 дней** и ваши лучшие и слабые ролики (`report.md`).
- **Разбор причин**: почему эти видео набрали больше обычного, по комментариям зрителей (`analysis.md`).
- **Ниша и кандидаты в конкуренты** (`niche.md`, `candidates.md`).
- **Контент-стратегия** (`strategy.md`): агент пишет черновик, утверждаете вы.
- **Брифы с упаковкой** для длинного видео, Shorts и поста в Сообщество, и **месячный план** из принятых брифов (`briefs/`, `plan.md`).

Проект ничего не публикует и не пишет в YouTube. Он помогает выбрать темы, а снимаете и выкладываете вы.

## Как это работает

1. **Настройка.** Вы описываете канал в `data/<канал>/settings.yaml`: ниша, регион и язык, слова для поиска.
2. **Сбор.** Агент считает расход квоты YouTube и ждёт вашего «да». Без ключа можно загрузить видео из файла.
3. **Залёты.** Скрипт находит видео, у которых просмотров заметно больше обычного для канала.
4. **Причины.** Агент читает комментарии залётов и пишет, о чём говорят зрители.
5. **Ниша и стратегия.** Агент собирает темы и форматы и пишет стратегию как черновик. Он останавливается, пока вы не поставите «утверждена».
6. **Брифы и план.** Агент делает брифы, вы ставите каждому «принят», «отклонён» или «позже», из принятых собирается план.
7. **Следующий месяц.** Агент помнит прошлые запуски: отклонённое не возвращается, «позже» можно вернуть.

## Что внутри

- `AGENTS.md` — общая инструкция агента; `playbooks/` — сценарии по шагам, начиная с `playbooks/00-month.md`;
- `templates/` — образцы файлов (стратегия, брифы, план); `examples/demo/` — тестовый канал и образцы результатов;
- `src/produce/` — скрипт сбора данных (`produce`); `site/` — страница-витрина.

## Установка и запуск

Что понадобится: компьютер с Linux, macOS или Windows (на Windows работайте внутри WSL: это Linux внутри Windows, без него проект не запустится), Python 3.12+ с модулем venv, `make` и `git` (две небольшие программы: `make` запускает готовые команды проекта, `git` копирует проект с GitHub) и ИИ-агент, который читает `AGENTS.md` (ИИ-шаги идут по вашей подписке на него, отдельного платного ключа ИИ нет).

### Windows: как поставить WSL (один раз)

WSL — это Linux внутри Windows; проект запускается в нём. Нужны Windows 10 версии 2004 и новее или Windows 11 ([инструкция Microsoft](https://learn.microsoft.com/windows/wsl/install)).

- **Шаг 1.** Нажмите «Пуск», найдите PowerShell, нажмите на нём правой кнопкой и выберите «Запуск от имени администратора».
- **Шаг 2.** Выполните команду `wsl --install` (она ставит Ubuntu, это и есть Linux).
- **Шаг 3.** Перезагрузите компьютер.
- **Шаг 4.** Откройте Ubuntu: после перезагрузки окно обычно открывается само, если нет, найдите Ubuntu в меню «Пуск». При первом запуске придумайте имя пользователя и пароль (пароль при вводе не показывается, это нормально) и запомните его.
- **Шаг 5.** В окне Ubuntu выполните `sudo apt update && sudo apt install -y git make python3-venv python3-pip` (спросит пароль из шага 4), затем `python3 --version`: должно быть 3.12 или новее.

Дальше все шаги ниже делайте в окне Ubuntu: `git clone`, `make setup` и запуск агента. Скачивать ZIP в Windows не нужно. Агент должен быть доступен внутри Ubuntu: как его поставить там, смотрите в документации вашего агента.

**Совет для Windows: надёжнее держать проект в домашней папке Ubuntu** (например, `~/youtube-producer`). Запуск из папки на диске Windows (путь начинается с `/mnt/c`) тоже работает через WSL, но там установка Python-пакетов может оборваться и оставить заблокированные файлы.

- **Как положить проект в домашнюю папку Ubuntu.** В окне Ubuntu выполните `cd ~`, затем `git clone https://github.com/ozerova152-lab/youtube-producer.git`: проект сразу окажется в `~/youtube-producer`.
- **Если вы уже скачали проект в Windows.** Скопируйте его в Ubuntu командой `cp -r /mnt/c/Users/ВАШЕ_ИМЯ/Downloads/youtube-producer ~/` (подставьте своё имя пользователя Windows и настоящее название папки; в окне Ubuntu диск C: виден как `/mnt/c`). Потом работайте только с копией: `cd ~/youtube-producer`.
- **Как проверить, где вы.** Выполните `pwd`. Если путь начинается с `/mnt/c`, это диск Windows: проект там запустится, но надёжнее скопировать его в домашнюю папку, как описано выше.
- **Если установка уже падала на диске Windows,** начните заново в домашней папке Ubuntu, а в старой папке на диске Windows `make setup` больше не запускайте.

1. **Скачайте проект и подготовьте его.** На Windows используйте `git clone` в окне Ubuntu (см. выше). Иначе на странице репозитория нажмите Code → Download ZIP и распакуйте архив (то же самое из терминала делает `git clone https://github.com/ozerova152-lab/youtube-producer.git`). Затем один раз выполните в терминале внутри папки `youtube-producer` команду `make setup`: она сама скачает всё нужное для работы (нужен интернет; после этого демо и импорт из файла идут без сети).
2. **Откройте папку** `youtube-producer` в вашем агенте (подсказки ниже).
3. **Скажите агенту:** «Прочитай AGENTS.md и запусти месяц». Вернуться к месту остановки: «Прочитай AGENTS.md и продолжи месяц».

Браузер Chromium (около 120 МБ) при `make setup` не скачивается: он нужен только разработчику для проверки страницы-витрины (`make setup-dev`, см. `docs/dev/setup.md`). **`make check` вам не нужен.** Это проверка для разработчика проекта, она работает только после `make setup-dev` (после обычного `make setup` она остановится с ошибкой «ruff: No such file or directory»).

Дальше агент сам спросит про настройки канала. Если файла настроек нет, он покажет образец `examples/demo/settings.yaml`: скопируйте его в `data/<канал>/settings.yaml`, заполните нишу, сегменты и слова, напишите «готово». Ключ YouTube не нужен, чтобы начать: можно посмотреть демо (раздел «Демо без ключа и без сети»), загрузить видео из файла или получить ключ позже.

### Ключ YouTube Data API (бесплатно, нужен для настоящего сбора)

Квота бесплатная: 10 000 единиц в день, типичному месяцу хватает с запасом. Платить ничего не нужно, банковская карта не требуется.

Кратко: в [Google Cloud Console](https://console.cloud.google.com/) создайте проект, включите **YouTube Data API v3**, создайте ключ API и ограничьте его (только YouTube Data API v3; «Application restrictions» оставьте None). Кнопку «Start free» не нажимайте.

**Подробная пошаговая инструкция для новичка: [docs/api-key-guide.md](docs/api-key-guide.md).**

Ключ лежит только в локальном файле `.env` в корне проекта. Он не попадает в git (внесён в `.gitignore`).

Записать его проще всего командой, текстовый редактор не нужен. В обычном терминале (в Windows это окно Ubuntu, не чат с агентом) в папке проекта выполните:

```bash
make add-key
```

Она спросит ключ (при вводе ничего не видно, это нормально; вставьте его, в терминале это обычно Ctrl+Shift+V), попросит повторить, сама создаст `.env` только для вас и ничего не покажет на экране. Если ключ уже записан, спросит, заменить ли его.

Другой способ, если привыкли править файл руками: выполните `cp .env.example .env`, откройте `.env` в любом текстовом редакторе и впишите строку:

```
YOUTUBE_API_KEY=ваш_ключ
```

Не вставляйте ключ в чат. Команды с полными путями и проверкой, что файл создан, — в разделе «Шаг 5» [инструкции](docs/api-key-guide.md). Агент `.env` не читает и ключ не показывает. Если ключ где-то засветился (чат, коммит, экран), перевыпустите его в Google Cloud: удалить недостаточно.

### Без ключа: импорт из файла

Если ключа нет, агент предложит выбрать: получить ключ или загрузить видео из файла CSV/JSON. Файл вы готовите сами. Формат колонок описан в [docs/import-format.md](docs/import-format.md), образец — `examples/demo/import.csv`. Импорт не ходит в сеть, квоту не тратит и подтверждения не требует:

```bash
.venv/bin/produce --channel data/<канал> import путь/к/файлу.csv
```

Без комментариев в файле причины залётов будут предположительными (по названиям и описаниям).

## Демо без ключа и без сети

Тестовый канал лежит в `examples/demo/`. Ничего платного и никаких правок кода:

```bash
mkdir -p data
cp -r examples/demo data/demo
.venv/bin/produce --channel data/demo start --segment ru --brief-lang ru
.venv/bin/produce --channel data/demo import examples/demo/import_comments.json --segment ru
.venv/bin/produce --channel data/demo virals --segment ru
```

Что должно получиться: `import` пишет «Загружено: 11 видео, 2 канала. Обращений к YouTube: 0», `virals` находит 2 залёта (например, «Как использовать нейросеть: выпуск 1», ×12.68 к норме канала). В файле `import_comments.json` есть комментарии, поэтому на шаге разбора агент показывает причины по комментариям, а не догадки по названиям. Дальше напишите агенту «Прочитай AGENTS.md и запусти месяц» на канале `data/demo`. Сбросить: `make reset`. Если `data/demo` уже есть, `cp` положит копию внутрь неё: сначала `make reset`.

## Примеры запросов

Агенту достаточно коротких фраз. Все они описаны в сценариях `playbooks/`:

- «Прочитай AGENTS.md и запусти месяц» — начать новый месяц или первый запуск;
- «Прочитай AGENTS.md и продолжи месяц» — вернуться к месту остановки после паузы, нового разговора или лимита подписки;
- «да» или «запусти сбор» — разрешить сбор после того, как агент показал расход квоты (без вашего слова он сбор не начнёт);
- «импорт путь/к/файлу.csv» — загрузить видео из файла вместо ключа;
- «ключ добавил» — после того как записали ключ командой `make add-key`;
- «готово» — когда заполнили `settings.yaml` или поставили в `strategy.md` статус «утверждена»;
- «пересчитай» — когда вы сами изменили пороги залётов в `settings.yaml` (поднять `views_multiplier`, например с 3 до 7, если залётов слишком много); пересчёт квоту не тратит.

## Если что-то не получилось

| Что видите | Что сделать |
|-----------|-------------|
| `make: command not found` или `python3: command not found` | Поставьте `make` и Python 3.12+ с модулем venv (Ubuntu/WSL: `sudo apt install -y make python3-venv python3-pip`). `python3 --version` должен показать 3.12 или новее |
| `make setup` падает, а путь проекта (`pwd`) начинается с `/mnt/c` | Проект лежит на диске Windows. Скопируйте его в домашнюю папку Ubuntu (см. правило в разделе «Windows: как поставить WSL») и запустите `make setup` там |
| `wsl --install` завис на 0% | В PowerShell от администратора выполните `wsl --install --web-download -d Ubuntu`: сначала скачается Ubuntu, потом поставится |
| `make setup` упал, в тексте «ensurepip is not available» | `sudo apt install python3-venv`, затем снова `make setup` |
| `make setup` упал с «No space left on device» | Освободите место на диске и повторите `make setup`; если успело создаться `.venv`, удалите его (`rm -rf .venv`) |
| «Ключ не подошёл (YouTube отклонил)…» | Ключ в `.env` с опечаткой, не тот или ограничен не тем сервисом. Перепроверьте по [инструкции](docs/api-key-guide.md); если ключ где-то засветился, перевыпустите его |
| «Квота на сегодня закончилась. Собрано N%, прогресс сохранён. Продолжите завтра» | Это не поломка: подождите до следующих суток по времени Google и напишите «продолжи месяц» |
| Агент не понимает фразу или отвечает не по сценарию | Проверьте, что открыта именно папка проекта (в ней лежит `AGENTS.md`). Пишите с началом «Прочитай AGENTS.md и …» |
| «Не найден файл настроек» | Нужен `data/<канал>/settings.yaml`: скопируйте образец `examples/demo/settings.yaml` (агент подскажет) |

## Слова, которые встретятся

- **Залёт** — видео, у которого просмотров заметно больше обычного для канала.
- **Норма канала** — типичные просмотры роликов этого канала; залёт сравнивают с ней («×12.68» — во столько раз выше).
- **Квота** — дневной лимит обращений к YouTube (10 000 единиц, бесплатно); перед сбором агент показывает расход.
- **Сегмент** — пара «регион + язык» в `settings.yaml` (например, ru и en); месяц идёт по одному сегменту.
- **Бриф** — задание на одно видео с названием и упаковкой; вы ставите ему статус «принят», «отклонён» или «позже».
- **Стратегия** — черновик, который агент пишет по найденному; дальше он ждёт, пока вы поставите «утверждена».
- **Запуск** — одна работа за месяц по сегменту, её файлы лежат в `data/<канал>/runs/`.
- **WSL** — Linux внутри Windows; на Windows проект запускается только в нём.

## Для чего проект не подходит и ограничения

- **Не публикует.** Он не загружает видео, не пишет в YouTube и не постит в Сообщество: решает и публикует всегда человек.
- **Только публичные числа.** Закрытой аналитики (удержание, доходы) нет: проект работает с публичной статистикой и комментариями.
- **Только официальный API или ваш файл.** Парсинга сайта YouTube нет. Данные идут через YouTube Data API с вашим ключом или из файла, который вы готовите сами.
- **Не работает сам по себе.** Автопилота и запуска по расписанию нет: на каждом шаге ждёт человек (квота, стратегия, статусы брифов).
- **Квота ограничена.** Бесплатно 10 000 единиц в день; если не хватило, прогресс сохраняется и сбор продолжается на следующий день.
- **Ещё нет:** VK Видео и превращения брифов в промпты для нейровидео.
- **Windows** только через WSL.
- **Основной путь — Claude Code.** В Codex проверены установка, сбор данных и поиск залётных роликов на реальном канале (30.10.2026); Cowork мы не проверяли. Для обоих используется тот же `AGENTS.md`, отдельных настроек и мини-скиллов под них нет (см. подсказки по агентам).

## Безопасность

Ключ YouTube лежит только в локальном `.env`, не вставляйте его в чат. **Запрет чтения `.env` в `.claude/settings.json` работает только в Claude Code.** В Cowork и Codex ключ держится лишь на инструкции в `AGENTS.md`, поэтому не включайте в них автоподтверждение команд и не вставляйте ключ в чат.

Не включайте автоподтверждение и в Claude Code, и читайте каждый запрос на выполнение команды перед тем, как согласиться. Названия видео и комментарии с YouTube попадают в отчёты, а их читает агент: чужой текст может попытаться уговорить его выполнить лишнее. Запреты в настройках и правила в `AGENTS.md` защищают от случайностей, но не заменяют ваше внимание.

Агент ничего не публикует и не пишет в YouTube; `--confirm` (подтверждение квоты) ставится только после вашего слова; стратегию утверждаете вы правкой файла `strategy.md`.
