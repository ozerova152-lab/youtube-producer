# AI-продюсер YouTube-канала

Набор инструкций, шаблонов и небольшой скрипт сбора данных. Вы открываете папку в своём Claude Code и пишете «запусти месяц». Агент находит залётные видео вашей ниши за 30 дней, разбирает причины по комментариям, предлагает стратегию, месячный план и брифы с упаковкой. **Решает и публикует всегда человек**: проект ничего не публикует и не пишет в YouTube.

Адрес репозитория: `https://github.com/ozerova152-lab/youtube-producer` (заглушка до публикации; кнопка и адрес обновятся при выкладке).

## Что понадобится

- компьютер с Linux, macOS или Windows через WSL (на нативном Windows без WSL проект не запускается: откройте WSL и работайте в нём);
- Python 3.12+ с модулем venv, `make`, `git`;
- Claude Code (его подписка делает ИИ-шаги; отдельного платного ключа ИИ нет);
- ключ YouTube Data API: бесплатный, но можно начать и без него (см. «Без ключа»).

## 1. Ключ YouTube Data API (бесплатно)

Квота бесплатная: 10 000 единиц в день, типичному месяцу хватает с запасом. Платить ничего не нужно, банковская карта не требуется.

Кратко: в [Google Cloud Console](https://console.cloud.google.com/) создайте проект, включите **YouTube Data API v3**, создайте ключ API и ограничьте его (только YouTube Data API v3; «Application restrictions» оставьте None). Кнопку «Start free» не нажимайте.

**Подробная пошаговая инструкция для новичка: [docs/api-key-guide.md](docs/api-key-guide.md).**

## 2. Куда положить ключ

Ключ лежит только в локальном файле `.env` в корне проекта. Он не попадает в git (внесён в `.gitignore`).

```bash
cp .env.example .env
# откройте .env и впишите: YOUTUBE_API_KEY=ваш_ключ
```

Не вставляйте ключ в чат. Команды с полными путями и проверкой, что файл создан, — в разделе «Шаг 5» [инструкции](docs/api-key-guide.md). Агент `.env` не читает и ключ не показывает. Если ключ где-то засветился (чат, коммит, экран), перевыпустите его в Google Cloud: удалить недостаточно.

## 3. Установка

```bash
git clone https://github.com/ozerova152-lab/youtube-producer.git
cd youtube-producer
make setup
```

`make setup` создаёт `.venv` и ставит зависимости. Заодно скачивается браузер Chromium (около 120 МБ): он нужен только для проверки страницы-витрины.

На Windows: сначала откройте WSL, все команды выполняйте в нём.

## 4. Первый запуск

1. Откройте папку проекта в Claude Code.
2. Напишите агенту: **«запусти месяц»**.
3. Агент спросит про настройки канала. Если файла нет, он покажет образец `examples/demo/settings.yaml`: скопируйте его в `data/<канал>/settings.yaml`, заполните нишу, сегменты и слова, напишите «готово».
4. Выберите сегмент и язык брифа.
5. Агент покажет **оценку квоты** (например, «Расход: ~430 из 10 000 единиц… Запускаем сбор?») и остановится. Сбор начнётся только после вашего «да».

Дальше агент идёт по шагам: залёты, разбор причин, ниша, стратегия. Стратегию он пишет черновиком и **останавливается**: если вы согласны, замените в `strategy.md` статус на «утверждена» и напишите «готово». Потом он делает брифы, а вы ставите в каждом статус «принят», «отклонён» или «позже»; из принятых собирается месячный план. Вернуться к месту остановки: «продолжи месяц».

Посмотреть всё на тестовых данных, ничего не тратя: `cp -r examples/demo data/demo`, затем «запусти месяц» на канале `data/demo`. Сбросить: `make reset`.

## Без ключа: импорт из файла

Если ключа нет, агент предложит выбрать: получить ключ или загрузить видео из файла CSV/JSON. Файл вы готовите сами. Формат колонок описан в [docs/import-format.md](docs/import-format.md), образец — `examples/demo/import.csv`. Импорт не ходит в сеть, квоту не тратит и подтверждения не требует:

```bash
.venv/bin/produce --channel data/<канал> import путь/к/файлу.csv
```

Без комментариев в файле причины залётов будут предположительными (по названиям и описаниям).

## В Codex

Отдельной поддержки Codex нет. Дайте ему ссылку на репозиторий и попросите: «Прочитай `CLAUDE.md` и работай по нему». Все инструкции лежат в обычных Markdown-файлах (`CLAUDE.md`, `playbooks/`). Честная пометка: **Codex проверен лишь на базовом уровне**, остальное, включая паузы агента, в нём не проверялось.

## Вариант без Claude Code

Для тех, у кого есть Claude Cowork, а Claude Code нет. **Запуск именно в Cowork мы не проверяли** (см. списки ниже).

1. На странице репозитория на GitHub нажмите Code → Download ZIP (адрес выше, пока заглушка).
2. Распакуйте архив.
3. Откройте распакованную папку в Claude Cowork. Как это делается, смотрите в его интерфейсе сами.
4. Напишите агенту дословно: **«Прочитай CLAUDE.md и запусти месяц»**.
5. Ключ YouTube: скопируйте шаблон `.env.example` в `.env` и впишите ключ в этот локальный файл (получение ключа: разделы 1 и 2 выше). Без ключа выберите импорт из файла: формат в [docs/import-format.md](docs/import-format.md).

**Проверено:**

- инструкции и сценарии на демо-данных и записанных ответах YouTube;
- команды скрипта (`produce`);
- тесты проекта (`make check`).

**Не проверено:**

- запуск именно в Claude Cowork;
- умеет ли Cowork в вашей среде запускать команды скрипта (Python, `make`): не обещаем, посмотрите сами;
- читает ли он `CLAUDE.md` сам;
- настоящий сбор по ключу.

**Про ключ.** Он лежит только в локальном `.env`, не вставляйте его в чат. Запрет чтения `.env` на уровне настроек (`.claude/settings.json`) работает только в Claude Code. В Cowork он держится лишь на инструкции в `CLAUDE.md`, поэтому проверьте сами, что агент ключ не показывает.

**Главное, как и везде:** агент ничего не публикует и не пишет в YouTube; `--confirm` (подтверждение квоты) ставится только после вашего слова; стратегию утверждаете вы правкой файла `strategy.md`.

## Что внутри

- `CLAUDE.md` — инструкция агента; `playbooks/` — сценарии по шагам, начиная с `playbooks/00-month.md`;
- `templates/` — образцы файлов (стратегия, брифы, план); `examples/demo/` — тестовый канал и образцы результатов;
- `src/produce/` — скрипт сбора данных (`produce`); `site/` — страница-витрина.

Проверка при разработке: `make check` (поиск секретов, линтер, тесты на записанных ответах YouTube; ключи и сеть не нужны).
