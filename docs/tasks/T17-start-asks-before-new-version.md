## Описание

Нашёл проверка покрытия (test-audit, пробел 3) и подтвердила ручная проверка: диагностический вызов
`produce start` на запуске «план готов» молча создал `2026-10_ru_v2`.

Правило: `start` на запуске «план готов» без явного разрешения не создаёт v2, а сначала спрашивает
человека. Явное разрешение — флаг `--new-version` (уже есть, его ставит агент только после слова
человека). Вопрос не ошибка: код выхода 0, ничего не пишется на диск.

Порядок по CLAUDE.md: сначала поток `docs/spec/04-user-flows.md` (поток 5, шаг 1, экран «Старт нового
запуска»), потом код и сценарии. Текст вопроса утверждён человеком: «В этом месяце уже есть v1, план
готов. Создать новую версию v2? Кэш скопируется, квота не тратится. Напишите «да», и я создам».
Старый текст «создам новую версию…» уходит.

Логика в ядре: `runs.start_run` на завершённом запуске без `force_new_version` возвращает новое
действие (например `"ask_new_version"`) и ничего не пишет; CLI только печатает вопрос.

Тесты, которые сейчас закрепляют старое поведение (v2 из `start` без флага), меняются осознанно по
решению человека: красный здесь — следствие нового правила, а не поломка. Таким тестам нужен
`force_new_version=True` или `--new-version`. Править их должен исполнитель, а доказывать новое
поведение — независимый тестировщик.

Затрагиваемые файлы: `docs/spec/04-user-flows.md`, `src/produce/core/runs.py`, `src/produce/cli.py`,
`playbooks/07-history.md`, `playbooks/00-month.md`, формулировки про повторный запуск в
`docs/spec/01…03`, тесты `tests/test_foundation.py`, `tests/test_foundation_verify.py`,
`tests/test_history.py`, `tests/test_history_verify.py` и новые тесты на критерии выше.

Важно: `tests/test_t16_verify.py::test_diff_boundaries` красный при любой несохранённой правке в
`src/`, `playbooks/`, `docs/spec/` и в чужих тестах. Пока он не решён, `run-task` не сможет получить
зелёный прогон до коммита.
