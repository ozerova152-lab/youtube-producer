## Описание

Ядро в `src/produce/core/`, команды в `cli.py` только вызывают ядро. Сделать: чтение `settings.yaml` (поля как в `examples/demo/settings.yaml`) и ключей из `.env`; выбор сегмента и языка брифа (`--segment`, `--brief-lang`); папку запуска `data/<канал>/runs/<ГГГГ-ММ>_<сегмент>_v<N>/` с `run.json` (месяц, сегмент, язык брифа, версия, этап, расход квоты, счётчик обращений к YouTube и ИИ, список неполных данных); безопасную запись (временный файл + переименование); сообщения об ошибках по-русски. Запрет сети в тестах: опция `--block-network` пакета pytest-recording в настройках pytest. Общие тестовые заготовки (временная папка канала, копия `examples/demo`, фиксированный ИИ) лежат в `tests/conftest.py`; каждая следующая задача сама добавляет в `examples/demo` нужные ей данные (кассеты и ответы ИИ). Шаги программы по порядку: `collect` → `virals` → `analyze` → `niche` → `strategy` → `briefs` → `plan`; отчёт запуска `report.md` собирается командой `produce report`, секции добавляют задачи шагов. Читай 02-tech-architecture.md (схема данных, секреты) и 03-dev-architecture.md (петля проверки).
