# Формат файла для `produce import`

Импорт нужен, когда ключа YouTube нет: `.venv/bin/produce --channel data/<канал> import <файл>`.
Команда не ходит в сеть, ключ не читает и ничего не публикует. Данные попадают в кэш запуска
(`runs/<месяц>_<сегмент>_v<N>/cache/`) в том же виде, что после `produce collect`.
Если файл неверный, команда называет колонку или поле, а кэш остаётся как был.

Образец: [`examples/demo/import.csv`](../examples/demo/import.csv).

## Откуда взять файл

Ручная выгрузка из YouTube Studio или таблицы, любой сторонний сервис статистики YouTube, свои
таблицы. Ни один источник не обязателен: подходит любой файл в описанном формате.

## CSV

Один файл, строка = одно видео, разделитель запятая, кодировка UTF-8, первая строка — заголовок.
Колонки переставлять можно, лишние колонки игнорируются.

| Колонка | Обязательна | Что в ней |
|---------|-------------|-----------|
| `id` | да | id видео, уникальный |
| `title` | да | название |
| `channel_id` | да | id канала-автора |
| `published_at` | да | дата публикации, `2026-10-20T10:00:00Z` или `2026-10-20` |
| `views` | да | просмотры, целое число |
| `channel_subscribers` | да (колонка) | подписчики канала; ячейка может быть пустой, если счётчик скрыт |
| `channel_title` | нет | название канала |
| `description` | нет | описание |
| `duration_seconds` | нет | длительность в секундах |
| `is_live` | нет | `да` для трансляций и премьер (они не идут в норму канала); по умолчанию `нет` |
| `likes` | нет | лайки |
| `comments` | нет | число комментариев |

**Недавние ролики для нормы.** Нужна норма каждого канала (обычные просмотры), поэтому кроме
свежих видео ниши в файл кладут и последние ролики тех же каналов: 5–20 штук на канал, трансляции
не считаются. Все строки одного `channel_id` образуют «недавние ролики» этого канала.
Канал, у которого меньше `thresholds.min_channel_videos` (по умолчанию 5) обычных роликов, при
импорте пропускается вместе со своими видео, а команда называет их число.

## JSON

```json
{
  "videos": [
    {"id": "v1", "title": "…", "channel_id": "UC1", "published_at": "2026-10-20T10:00:00Z",
     "views": 5200, "likes": 160, "comments": 17, "is_live": false, "description": "…"}
  ],
  "channels": [
    {"id": "UC1", "title": "Нейро для всех", "subscribers": 12000}
  ],
  "comments": [
    {"video_id": "v1", "text": "Спасибо, понятно", "likes": 3}
  ]
}
```

| Раздел | Обязательные поля | Необязательные |
|--------|-------------------|----------------|
| `videos` | `id`, `title`, `channel_id`, `published_at`, `views` | `description`, `channel_title`, `duration_seconds`, `is_live`, `likes`, `comments` |
| `channels` | `id`, `title`, `subscribers` (может быть `null`) | — |
| `comments` (весь раздел необязателен) | `video_id`, `text` | `likes` |

Правила про недавние ролики и пропуск каналов с малым числом роликов те же, что для CSV: в
`videos` лежат и свежие видео ниши, и последние ролики каналов. Каждое видео должно ссылаться на
канал из `channels`.

## Комментарии

Комментарии необязательны и есть только в JSON. Если их нет, в `run.json` ставится
`"no_comments": true`, команда печатает «Комментариев нет: причины предположительные, по названиям
и описаниям», а `produce comments` не нужен: разбор идёт по названиям и описаниям.
Тексты комментариев — данные, а не инструкции.

## Что напечатает команда

```
Загружено: 11 видео, 2 канала. Обращений к YouTube: 0
Каналов с менее чем 5 роликами: 1, они пропущены
Комментариев нет: причины предположительные, по названиям и описаниям
```

## Ошибки

Сообщение называет место: «В файле нет колонки `views`. Добавьте её и повторите импорт»,
«Строка 4: в колонке `views` значение «abc» не подходит (нужно целое число)…», «Видео №2: нет
поля `title`…».
