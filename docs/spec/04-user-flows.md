**Что здесь «экран».** У самого продукта (потоки 1–5) нет окон: «экран» — это сообщение агента в чате, вывод команды `produce` в терминале или Markdown-файл, который человек читает и правит руками. Внешность не описывается: только содержание и тексты. Терминал на десктопе (Linux, Mac, WSL); на нативном Windows — через WSL (ветка в потоке 1). Единственные настоящие экраны — у потока 6: статическая страница-витрина в браузере (десктоп и телефон).

## Карта потоков

| Поток | Задача человека | Фичи слоя 1 | Сценарии петли (слой 3) |
|-------|-----------------|-------------|-------------------------|
| 1. Первый запуск | Поставить репозиторий, настроить канал, дойти до оценки квоты (или импорта) | Публикация на GitHub/README, файл настроек, импорт из файла | Настройки, третий сегмент; Нет ключа / неверный; Импорт из файла; Чистая установка |
| 2. Сбор и залёты | Подтвердить квоту, собрать данные, увидеть залёты и свои результаты, получить разбор причин | Оценка квоты и сбор, мои результаты, поиск залётов, разбор причин | Оценка квоты и подтверждение; Сбор, пустой список конкурентов; Мои результаты; Залёты; Комментарии только залётов; Сбой и квота; Разбор причин; Устойчивость к инъекции и ключ |
| 3. Ниша и стратегия | Понять нишу, получить кандидатов и утвердить стратегию | Анализ ниши и конкурентов, контент-стратегия | Ниша и кандидаты; Стратегия с паузой |
| 4. Брифы и план | Получить брифы, решить по каждому, получить месячный план | Брифы трёх видов, статусы брифов, месячный план, проверка файлов агента | Брифы трёх видов; Статусы, план, пределы; Битые файлы агента |
| 5. Новый месяц | Запустить следующий месяц без повторов отклонённого, вернуть брифы «позже» | История запусков | Повторный запуск; История |
| 6. Посетитель страницы-витрины | Понять, что за проект, как запустить, и перейти в репозиторий | Страница-витрина | — (слой 3 не покрывает, см. «Вопросы») |

## Поток 1: Первый запуск

- **Кто и откуда:** впервые; пришёл с GitHub по README; в Claude Code, Claude Cowork или Codex открыта папка проекта. Фраза старта: Claude Code — «запусти месяц»; Cowork и Codex — «Прочитай AGENTS.md и запусти месяц» (Codex: человек даёт ссылку на репозиторий). Вернуться к месту остановки: «продолжи месяц» (в Cowork и Codex с тем же началом). Дальше то же самое.
- **Успех:** человек видит оценку квоты (запись «ожидает подтверждения», обращений 0) или результат импорта; ключ нигде, кроме `.env`, не лежит.

1. [Внешний: GitHub README] Человек читает раздел «Установка и запуск» из трёх шагов («1. Скачайте проект: `git clone …`, `make setup`. 2. Откройте папку в любом агенте, который читает `AGENTS.md`. 3. Напишите: «Прочитай AGENTS.md и запусти месяц»»; ниже короткие подсказки для Claude Code, Cowork и Codex), на Windows открывает WSL, ключ можно получить позже, начать можно с демо-данных; не получилось: раздел «Если что-то не получилось» → возврат: пишет агенту фразу старта → [Экран: Старт месяца]
   - Ветка «Windows без WSL»: README коротко и простыми словами ведёт по установке WSL (PowerShell от имени администратора, `wsl --install`, перезагрузка, открыть Ubuntu и создать имя пользователя и пароль, поставить `git`, `make`, `python3-venv`) и говорит, что дальше все шаги делаются в окне Ubuntu и советует держать проект в домашней папке Ubuntu (например, `~/youtube-producer`); запуск с диска Windows (`/mnt/c…`) тоже работает через WSL, но надёжнее домашняя папка: на диске Windows установка Python-пакетов может оборваться и оставить заблокированные файлы; как скопировать проект в домашнюю папку, README объясняет простыми словами; своих команд для Windows вне WSL нет.
2. [Экран: Старт месяца] Агент ищет `settings.yaml` канала → если нет, переходит на [Экран: Нужны настройки] → после «готово» читает файл
   - Ветка «файл с ошибкой»: → [Экран: Ошибка настроек]
3. [Экран: Нужны настройки] Агент называет файл-образец `examples/demo/settings.yaml`, объясняет поля (ниша, сегменты, слова, пороги, мой канал) → человек копирует в `data/<канал>/`, правит руками, пишет «готово» → [Экран: Старт месяца], проверка файла
4. [Экран: Выбор сегмента и языка] Агент показывает список сегментов (`produce segments`) и спрашивает сегмент и язык брифа (язык сегмента или русский) → человек отвечает → [Система]
5. [Система] Агент запускает `collect` без `--confirm` (`.env` сам не читает); человек видит «Считаю расход квоты…» (оценка не ходит в сеть, обращений 0; скрипт только смотрит, есть ли ключ) → ключ есть: [Экран: Оценка квоты] (поток 2, шаг 1); ключа нет: [Экран: Ключ YouTube]
6. [Экран: Ключ YouTube] Две дороги → человек выбирает
   - «Ключ»: [Внешний: Google Cloud] человек по README получает бесплатный ключ и записывает его командой `make add-key` в обычном терминале (без текстового редактора: ввод скрыт, права на `.env` только для владельца) → [Экран: Ввод ключа] → возврат: пишет «ключ добавил» → [Экран: Оценка квоты] (поток 2)
   - «Файл»: человек пишет «импорт <файл>» → [Система: импорт] → [Экран: Импорт выполнен] → дальше поток 2, шаг «Залёты»
   - Ветка «файл неверного формата»: → [Экран: Ошибка импорта]

## Поток 2: Сбор и залёты

- **Кто и откуда:** впервые — из потока 1; повторно — открыл папку и написал «продолжи месяц» → [Экран: Где мы остановились] (этап читается из `run.json`).
- **Повторные действия:** подтверждение действует один раз: после сбоя, остановки или нового разговора агент спрашивает «да» заново (слово человека берётся в этом разговоре); повторный сбор на тех же данных квоту не тратит (кэш). Обновление страницы не нужно: состояние лежит в файлах.
- **Успех:** в папке запуска `virals.json`, `report.md` и `analysis.md`; человек знает, какие видео залетели и почему.

1. [Экран: Оценка квоты] Видит короткую сводку (расход из 10 000, число поисков и запросов, хватит ли на сегодня) и вопрос «Запускаем сбор?» → пишет «да» (молчание и «ну ок, посмотрим» не считаются) → агент запускает `collect --confirm`
   - Ветка «не хватает на сегодня»: сводка говорит сколько осталось, предлагает продолжить завтра; сбор не стартует.
   - Ветка «нет»: запуск остаётся «ожидает подтверждения»; агент: «Хорошо, жду. Скажите «запусти сбор», когда будете готовы» → [Экран: Оценка квоты]
2. [Система] Сбор: человек видит «Собираю: поиск 2 из 4…» → [Экран: Итог сбора]
   - Ветка «ключ неверный»: → [Экран: Ключ YouTube], состояние «неверный»
   - Ветка «сбой сети»: после 3 повторов → [Экран: Сбой сбора]
   - Ветка «квота исчерпана»: → [Экран: Квота кончилась]
3. [Экран: Итог сбора] Видит число найденных видео и каналов, расход квоты, число обращений, пометку «неполные данные: N» → агент сразу считает залёты
4. [Система] `virals` и `report` → [Экран: Залёты и мои результаты]
5. [Экран: Залёты и мои результаты] Видит таблицу залётов (название, просмотры, норма канала, во сколько раз выше) и мои лучшие и слабые ролики → решает, идти ли к причинам
   - Ветка «залётов нет»: → [Экран: Залётов нет]
   - Ветка «мой канал не задан»: блок «Мои результаты» заменён пометкой, поток идёт дальше.
6. [Экран: Оценка квоты на комментарии] Сводка расхода на комментарии только залётов и «Докачать комментарии?» → «да» → [Система] `comments --confirm` → шаг 7
   - Ветка «нет»: разбор идёт по названиям и описаниям, как при импорте без комментариев.
   - Ветка «сбой сети или квота»: → [Экран: Сбой сбора] / [Экран: Квота кончилась]
   - Ветка «импорт без ключа и без комментариев в файле»: этот шаг пропускается; агент пишет «Комментариев нет: причины предположительные, по названиям и описаниям» → шаг 7 с пометкой вверху `analysis.md`; блок «Мои результаты» пропущен с пометкой, если моего канала нет в файле
7. [Экран: Разбор готов] Агент по частям (по видео) записывает темы и эмоции в `analysis.md`, `check-files` зелёная → человек читает файл → поток 3
   - Ветка «меньше 10 комментариев»: у видео пометка «мало комментариев», эмоций нет.
   - Ветка «проверка красная»: → [Экран: Проверка файлов], агент исправляет и не идёт дальше.
   - Ветка «лимит подписки кончился» (на любом шаге агента в потоках 2–5): → [Экран: Лимит агента]

## Поток 3: Ниша и стратегия

- **Кто и откуда:** из потока 2 после «Разбор готов» или с «продолжи месяц» при этапе «разбор готов».
- **Успех:** есть `niche.md`, `candidates.md` и `strategy.md` со статусом «утверждена», выставленным человеком.

1. [Система] Агент по сценарию пишет `niche.md` и `candidates.md` → [Экран: Ниша и кандидаты]
2. [Экран: Ниша и кандидаты] Видит темы и форматы залётов (длинные от 3 мин / Shorts), повторяющиеся каналы и кандидатов в конкуренты с причиной у каждого; сообщение «`settings.yaml` не менял» → хочет добавить кандидата — правит `settings.yaml` сам → [Экран: Вводные для стратегии]
3. [Экран: Вводные для стратегии] Агент спрашивает по одному: тема, цель, аудитория, время и силы в неделю → человек отвечает → [Система]
4. [Система] Агент пишет `strategy.md` со статусом «черновик» и запускает `check-files` по стратегии (поля, повтор отклонённых тем) → [Экран: Проверка файлов] → зелёная: [Экран: Пауза: стратегия]
5. [Экран: Пауза: стратегия] Видит баланс форматов (длинные, Shorts, посты) и частоту, фразу «Я остановился. Прочитайте `strategy.md`; если согласны — замените статус на «утверждена» и напишите «готово»» → правит файл и пишет «готово»
   - Ветка «хочу правки»: пишет, что изменить → агент правит черновик, статус остаётся «черновик» → снова [Экран: Пауза: стратегия]
   - Ветка «говорит агенту „утверждаю“, а в файле нет»: агент отвечает «В файле статус «черновик». Замените его сами и напишите «готово»» → [Экран: Пауза: стратегия]
6. [Экран: Стратегия утверждена] Агент проверяет статус; «утверждена» → сообщение «Стратегия утверждена, перехожу к брифам» → поток 4
   - Ветка «битая строка статуса»: → [Экран: Проверка файлов]

## Поток 4: Брифы и план

- **Кто и откуда:** из потока 3 после утверждения стратегии.
- **Успех:** `plan.md` содержит только принятые брифы; число роликов в пределах настроек.

1. [Система] Агент пишет брифы по частям; человек видит «Бриф 3 из 8: Shorts «…»» → [Экран: Проверка файлов]
2. [Экран: Проверка файлов] `produce check-files --step briefs`: зелёная — «Проверено брифов: 8, ошибок нет» и дальше; красная — название файла, место и что исправить, агент правит и не двигается → [Экран: Брифы на решение]
3. [Экран: Брифы на решение] Видит таблицу брифов (номер, вид, название, на каких образцах основан) и «Откройте брифы в `briefs/`, в каждом поставьте статус: принят / отклонён / позже, и напишите «готово»» → ставит статусы руками → пишет «готово»
   - Ветка «часть статусов пуста»: агент называет брифы без решения («Нет статуса: 2, 5») и ждёт → [Экран: Брифы на решение]
4. [Система] Агент собирает `plan.md` из принятых → [Экран: Месячный план]
5. [Экран: Месячный план] Видит список принятых брифов по неделям, число роликов и пределы из настроек → читает `plan.md`
   - Ветка «принятых меньше минимума»: «Принятых 3, минимум 4. Нехватка: 1. План не добит. Могу сделать ещё брифы или вы смените статус «позже» на «принят»» → поток 4, шаг 1 или шаг 3
   - Ветка «принятых больше максимума»: «Принятых 9, максимум 8. Перенесите лишние в «позже» и напишите «готово»»; сам агент не режет → шаг 3
6. [Экран: Проверка файлов] `check-files --step plan` зелёная → «Месяц готов. Публикацию делаете вы» → конец потока

## Поток 5: Новый месяц

- **Кто и откуда:** повторно, через месяц или при повторном запуске в том же месяце; открыл папку и написал «запусти месяц».
- **Успех:** создан новый запуск (папка `runs/…_v<N>`), прошлые целы; отклонённые темы не повторены.

1. [Экран: Старт нового запуска] Агент видит прошлые запуски. Если запуск этого месяца и сегмента не дошёл до этапа «план готов», предлагает продолжить его ([Экран: Где мы остановились]); v2 — только после «план готов». Иначе пишет «За 2026-11 для сегмента ru ещё нет запуска. Создаю…», а на запуске «план готов» ничего не создаёт и спрашивает: «В этом месяце уже есть v1, план готов. Создать новую версию v2? Кэш скопируется, квота не тратится. Напишите «да», и я создам» (номера — от последней версии: при v2 — «уже есть v2 … новую версию v3»; код выхода 0, на диск ничего не пишется). Новая версия создаётся только после слова «да» человека в этом разговоре (агент ставит `--new-version`); после «да» скрипт пишет «В этом месяце уже есть v1: создаю новую версию, кэш копирую, квота не тратится» и «Запуск 2026-11_ru_v2 создан. Этап: настроен» → человек подтверждает сегмент и язык брифа
2. [Экран: Что уже было] История берётся только из запусков того же сегмента (сегменты не смешиваются, ru и en отдельно). Видит список отклонённых и уже предложенных тем прошлых запусков и брифы «позже» → решает, возвращать ли «позже»
3. [Система] `later` возвращает выбранные брифы «позже» в новый запуск → человек видит «Возвращено брифов: 2»
4. [Экран: Оценка квоты] Дальше поток 2 (с шага 1), потом 3 и 4; на тех же данных повтор квоты не тратится
5. [Экран: Повтор темы] При проверке файлов стратегии или брифов находится тема, отклонённая раньше → «Тема «…» отклонена в 2026-09 (бриф `…`). Замените её» → агент заменяет и проверка повторяется
   - Ветка «человек хочет вернуть отклонённую»: меняет статус руками в старом брифе; агент сам не возвращает.

## Поток 6: Посетитель страницы-витрины

- **Кто и откуда:** гость без входа; впервые; пришёл по ссылке из поста, чата или поиска, с телефона или компьютера.
- **Успех:** посетитель понял, что делает проект, и нажал «Скачать на GitHub» (или скопировал адрес репозитория).

1. [Внешний: ссылка из поста, чата или поиска] Открывает адрес страницы → возврат не нужен → [Экран: Витрина, блок «О проекте»]
2. [Экран: Витрина, блок «О проекте»] Видит заголовок, одно предложение о проекте и кнопку «Скачать на GitHub» → читает дальше или сразу нажимает кнопку (шаг 7)
3. [Экран: Витрина, блок «Как это работает»] Видит 5 шагов-потоков по одной строке и фразу «Решает и публикует всегда человек» → листает
4. [Экран: Витрина, блок «Как запустить»] Видит три общих шага («Скачайте проект и один раз подготовьте его», «Откройте папку проекта в вашем агенте», «Скажите агенту: «Прочитай AGENTS.md и запусти месяц»») и под ними три подсказки одинаковой длины: Claude Code, Claude Cowork и Codex (как открыть папку), и под ними строку «Основной путь — Claude Code. В Codex проверены установка, сбор данных и поиск залётных роликов на реальном канале (30.10.2026). Cowork мы не проверяли: используйте тот же AGENTS.md и пишите в Issues»; строку «Нет ключа YouTube? Можно загрузить видео из файла» → листает
5. [Экран: Витрина, блок «Пример результата»] Видит фрагмент таблицы залётов и кусок брифа с подписью «Пример на демо-данных, не реальный канал» → листает
6. [Экран: Витрина, нижний призыв] Видит кнопку «Скачать на GitHub» и под ней адрес репозитория текстом → нажимает кнопку (или «Скопировать адрес»: надпись меняется на «Адрес скопирован»)
   - Ветка «браузер не дал скопировать»: под кнопкой появляется «Не получилось скопировать. Выделите адрес вручную»; адрес остаётся на экране текстом → выделяет и копирует сам
7. [Внешний: GitHub] Открывается страница репозитория → возврат: кнопка «Назад» браузера возвращает на то же место страницы

## Задания для живого теста (3 человека × 15 минут)

| Поток | Задание (без подсказок интерфейса) | Смотрим |
|-------|-------------------------------------|---------|
| 1. Первый запуск | «Вы нашли этот репозиторий на GitHub. У вас нет ключа YouTube. Доберитесь до того, чтобы он показал вам видео вашей ниши» | Застревание на выборе «ключ или файл», на создании `settings.yaml` руками |
| 2. Сбор и залёты | «Агент написал про расход квоты. Решите, запускать ли, и посмотрите, какие видео залетели» | Понятна ли сводка квоты; не считает ли человек «ну ок» разрешением |
| 3. Ниша и стратегия | «Агент остановился после стратегии. Продолжите работу» | Понимает ли, что статус меняется самим человеком в файле |
| 4. Брифы и план | «Из восьми брифов вам нужны три. Получите план» | Находит ли файлы брифов, ставит ли статусы, понимает ли сообщения про нехватку и избыток |
| 5. Новый месяц | «Прошёл месяц. Одна тема в прошлый раз вам не понравилась. Сделайте новый месяц так, чтобы она не вернулась» | Видит ли историю отклонённых тем, понимает ли «v2» |
| 6. Посетитель страницы-витрины | «Вам прислали ссылку на проект. С телефона разберитесь, что это, и решите, подходит ли оно вам» | Понимает ли за 10 секунд, что это и для кого; находит ли путь с телефона к репозиторию; не принимает ли «Скачать» за готовую программу |

## Вопросы, на которые спека не отвечает

- Слой 3 не покрывает витрину: нужны проверки (ширина 360 px без горизонтальной прокрутки, отсутствие ключей на странице, ссылка на репозиторий). Добавить в петлю при следующей правке слоя 3.
- Адрес репозитория для кнопки неизвестен до публикации (репозиторий пока приватный); подставляется при публикации.

- Какие слова считаются «словом человека» («да», «готово», «запусти сбор»): в `AGENTS.md` пока общее правило; список принимаемых слов определить в `playbooks/01-collect.md`.
