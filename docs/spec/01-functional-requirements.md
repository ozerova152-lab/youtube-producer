# Функциональные требования — AI-продюсер YouTube-канала

> Слой 1 из 3 · «ЧТО и для кого» · Дата: 2026-10-22

## Продукт одним предложением

Локальная программа (не сайт), которая через официальный YouTube Data API находит залетевшие за 30 дней видео в нише канала, разбирает причины залёта и по шагам (стратегия → месячный план → брифы) помогает автору малого канала решить, какие ролики снимать; публикует и решает всегда человек.

## Для кого

- **Основная аудитория:** автор малого канала (у первого пользователя ~400 подписчиков, тематика нейросети, простой монтаж), делает ролики сам. Задача: понять, какие темы реально набирают просмотры и охваты, и не выбирать тему наугад.
- **Вторичная:** любой автор любой ниши, кто возьмёт программу с GitHub и подставит свой ключ API. Универсальность только через файл настроек; кроме короткого README подробные обучающие материалы и поддержку для чужих пока не делаем.
- **НЕ аудитория:** крупные каналы и студии (инструмент заточен под малый канал); те, кто ищет автопубликацию или «канал на автопилоте»; те, кому нужна закрытая аналитика своего канала.
- **Рынок / география:** сегменты (регион поиска + язык анализа) задаются списком в настройках. На старте два: русскоязычный и англоязычный; новые (Индия, Азия, Европа, Африка…) добавляются записью в файл без переписывания программы. Сегменты не смешиваются. Язык брифа: язык сегмента или русский, выбор при запуске. Ниша, язык и аудитория не вшиты в код.

## Фичи (весь объём — что не в списке, того не будет)

| Фича | Что делает | Готово, когда (дано — когда — тогда) |
|------|-----------|--------------------------------------|
| Файл настроек канала | Ниша, аудитория, языки, сегменты, ключевые слова, каналы-конкуренты (необязательно), пороги залёта, пределы частоты публикаций | Дано файл с двумя сегментами; когда добавляю третий записью в файл; тогда он доступен при запуске без правки кода |
| Публикация на GitHub со своим ключом | Программа лежит на GitHub; каждый пользователь работает со своим ключом YouTube Data API. В комплекте короткий README: как получить ключ в Google Cloud, куда его положить (локальный файл, исключённый из репозитория), как сделать первый запуск | Дано чистая копия репозитория и README; когда следую ему по шагам со своим ключом; тогда первый запуск доходит до оценки квоты без правок кода. Дано ключ в локальном файле; когда смотрю содержимое репозитория и историю; тогда ключа там нет |
| Выбор сегмента и оценка квоты | При запуске выбираю сегмент и язык брифа; программа показывает ожидаемый расход квоты API, включая запросы за статистикой каналов найденных авторов | Дано заполненные настройки; когда запускаю; тогда вижу оценку расхода (поиск + статистика каналов + комментарии) и запуск идёт только после моего «да» |
| Сбор данных | Ищет видео за 30 дней по ключевым словам и (если список не пуст) смотрит ролики каналов-конкурентов; для каждого найденного автора добирает его последние ролики, чтобы посчитать норму канала | Дано пустой список конкурентов; когда запускаю сбор; тогда работает только поиск по словам и ошибки нет |
| Мои результаты | Берёт публичную статистику моего канала (просмотры, лайки, комментарии по роликам) | Дано мой канал в настройках; когда запускаю; тогда в отчёте есть мои лучшие и слабые ролики |
| Поиск залётов | Отбирает видео: просмотры ≥ 3× нормы канала и вовлечённость выше порогов; скорость набора просмотров только как доп. сигнал. Норма канала = медиана просмотров его последних 10 обычных роликов без проверяемого; если роликов меньше 5, видео пропускается с пометкой «мало данных». Пороги по умолчанию (меняются в настройках): лайки ≥ 2% и комментарии ≥ 0,1% от просмотров | Дано пороги по умолчанию; когда сбор завершён; тогда в списке видео, прошедшие все пороги, с числами просмотров, нормы канала и вовлечённости. Дано ни одного прошедшего; тогда показаны 5 ближайших к порогу и предложение ослабить пороги, файл настроек не меняется |
| Разбор причин | Для отобранных видео анализирует до 100 самых популярных комментариев: темы и эмоции, что триггерит зрителей | Дано видео с ≥ 10 комментариев; когда идёт разбор; тогда у него есть главные эмоции и темы на выбранном языке. Дано меньше 10; тогда эмоции не выводятся, стоит пометка «мало комментариев» |
| Анализ ниши и конкурентов | Сводка по нише: какие темы и форматы (длинные / Shorts) чаще среди залётов, какие каналы повторяются; предлагает кандидатов в конкуренты | Дано сегмент; когда разбор готов; тогда в отчёте есть темы, форматы и кандидаты в конкуренты (с причиной), а в файл настроек они не добавлены |
| Контент-стратегия (этап 1) | По моим вводным (тема, цель, аудитория, время и силы) и залётам предлагает баланс форматов (длинные от 3 мин, Shorts до 3 мин, посты в Сообществе) и частоту | Дано вводные и результаты анализа; когда запрашиваю стратегию; тогда получаю файл стратегии и программа останавливается. Я правлю файл руками или запускаю этап заново; этап 2 не стартует, пока я не утвердил стратегию |
| Месячный план (этап 2) | По утверждённой стратегии строит план; число роликов вытекает из стратегии, по умолчанию и в пределах из настроек | Дано утверждённая стратегия; когда строю план; тогда в плане только принятые брифы, число роликов в пределах настроек. Принятых меньше минимума: программа сообщает нехватку и предлагает вернуть брифы «позже» или сгенерировать новые, но не добивает план сама. Принятых больше максимума: я сам переношу лишние в «позже» |
| Брифы трёх видов | Единая чёткая структура у каждого вида. Длинное видео: идея, на каком залёте основана и чем отличаемся, структура по частям с пометками по монтажу, первые 15 с, длина. Shorts: хук, идея, сценарий на 30–60 с с пометками по монтажу. Пост в Сообщество: идея опроса или картинки (данных Сообщества в API нет, идеи только по трендам). В каждом: 2–3 видео-образца и главные эмоции из комментариев; упаковка — см. следующую фичу | Дано план; когда открываю бриф; тогда все обязательные поля вида заполнены, образцы со ссылками, в структуре есть пометки по монтажу |
| Упаковка в брифе | В бриф длинного видео и Shorts входят: 2–3 варианта названия, описание в двух вариантах (триггерное и SEO для поиска), хэштеги и теги, идея обложки. Для поста в Сообщество — готовый текст поста | Дано бриф длинного видео или Shorts; когда открываю; тогда есть 2–3 названия, два описания (триггерное и SEO), хэштеги и теги, идея обложки. Дано бриф поста; тогда есть готовый текст, который можно вставить как есть |
| Статусы брифов | После генерации брифов, до построения плана, я помечаю каждый: принят / отклонён / позже | Дано бриф; когда ставлю «отклонён»; тогда он не попадает в план |
| История запусков | Каждый запуск (календарный месяц + сегмент) хранится отдельно; повторный запуск в том же месяце создаёт новую версию, прежняя остаётся; следующий видит прошлые темы и статусы | Дано предложенная и отклонённая тема в прошлом месяце; когда идёт новый запуск; тогда тема не предлагается повторно, а брифы «позже» можно вернуть |

## Нефункциональные требования (поведение в сложных условиях)

- Квота API ограничена (~10 000 единиц в день, поиск дорогой): расход оценивается заранее, ждёт моего «да».
- Квота кончилась посреди запуска: собранное и прогресс сохраняются. Критерий: дано квота исчерпана на половине сбора; когда запускаю на следующий день; тогда сбор идёт с того же места, уже собранное не тратит квоту повторно.
- Сбой API или сети: 3 повтора с растущей паузой, затем остановка с понятным сообщением и сохранённым прогрессом. Критерий: дано API недоступен; когда запрос упал 3 раза; тогда запуск остановлен, прогресс сохранён, причина названа.
- Нет данных (мало роликов у канала, нет комментариев): видео пропускается с пометкой причины, а не угадывается.
- Результаты, подготовленные на неполных данных (пропущенные видео, остановка по квоте), помечены как неполные. Критерий: дано часть видео пропущена; когда открываю отчёт; тогда на нём стоит пометка «неполные данные» с числом пропущенных.
- Нет ключа API или он неверный: при запуске понятное сообщение, как его задать, без падения и без запросов. Все сообщения и отчёты программы по-русски (язык брифа выбирается отдельно).
- Ключи API лежат только на компьютере пользователя и не попадают в репозиторий и отчёты.
- Агент ничего не публикует, не пишет в YouTube и не меняет файл настроек сам.
- Данные берутся только из официального YouTube Data API.

## Открытые вопросы

- Решено в слое 2: анализ делает платный Claude API в пределах потолка 1 000 ₽ в месяц; «оплат не нужно» в слое 1 относилось к продукту (оплаты пользователей, хостинг), а не к ИИ.
- Пороги залёта по умолчанию (3×, 2%, 0,1%, медиана 10 роликов) — стартовые, уточним на реальных данных канала; они лежат в настройках.
