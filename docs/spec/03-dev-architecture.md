# Девелоперская архитектура — AI-продюсер YouTube-канала

## Запуск одной командой

- **Установка:** `make setup` → виртуальное окружение Python и зависимости.
- **Проверки одной командой:** `make check` → все автопроверки на записанных данных; ключи, сеть и деньги не нужны.
- **Для человека:** программа запускается командой `produce <шаг>` (`collect` → `virals` → `analyze` → `niche` → `strategy` → `briefs` → `plan`); `produce report` собирает `report.md` запуска, `produce later` возвращает брифы «позже» из прошлых запусков. Сегмент выбирается флагом `--segment ru` (без флага программа спрашивает), язык брифа — `--brief-lang`, подтверждение расхода квоты — вопрос «да/нет» (в тестах флаг `--yes`). `produce --channel examples/demo` работает на тестовом канале без ключей, на записанных данных.
- **Счётчик обращений:** в `run.json` хранятся число запросов к YouTube и ИИ и расход квоты; по нему проверяется «0 реальных обращений».

## Тестовые данные и сброс

- **Seed (`examples/demo/`, в репозитории):** настройки тестового канала с двумя сегментами (RU, EN); записанные ответы YouTube (кассеты): ~10 видео, из них часть залётных, часть нет, канал с менее чем 5 роликами, видео с меньше чем 10 комментариев; пустой список конкурентов и заполненный.
- **Сброс:** `make reset` → удаляет папку данных тестового канала (`data/demo/`), возвращает чистое состояние.
- Ключи в кассетах вырезаются при записи; у кассеты есть дата записи, `make check` предупреждает, если она старше 6 месяцев (формат ответа YouTube мог измениться).

## Петля проверки (запустил → прогнал → доказал → починил)

| Сценарий (из фич слоя 1) | Как ИИ прогоняет | Чем доказывает результат |
|--------------------------|------------------|--------------------------|
| Настройки и сегменты: добавить третий сегмент записью | Тест правит копию настроек, запускает команду выбора сегмента | Вывод команды содержит новый сегмент; код не менялся |
| Оценка квоты и «да» | `produce collect` на демо-канале без подтверждения | Показан расчёт расхода (поиск + статистика + комментарии); без «да» в журнале запросов 0 вызовов |
| Мои результаты | Запуск на кассете с моим каналом | В отчёте названы лучшие и слабые ролики моего канала с числами |
| Анализ ниши и кандидаты | Запуск разбора на демо-данных | В отчёте темы и форматы (длинные / Shorts); `candidates.md` с причиной у каждого; хэш `settings.yaml` до и после совпадает (файл не изменён, в том числе при нуле залётов) |
| Язык брифа | Запуск с `--brief-lang` сегмента и `ru` | Бриф написан на выбранном языке, остальные сообщения программы по-русски |
| Сбор данных, пустой список конкурентов | Запуск на кассетах без конкурентов | `cache/videos.json` создан, ошибки нет |
| Поиск залётов: пороги и норма канала | Запуск на кассетах с известными числами | `virals.json` содержит ровно ожидаемые видео; видео с < 5 роликами у канала пропущено с пометкой «мало данных»; при нуле залётов — 5 ближайших к порогу |
| Разбор причин (комментарии) | Фиксированный ответ ИИ-провайдера | В `virals.json` у видео есть эмоции и темы; при < 10 комментариев — пометка «мало комментариев», эмоций нет |
| Стратегия с паузой | `produce strategy`, затем попытка `produce plan` без утверждения | `strategy.md` создан со статусом «черновик»; `plan` отказывается с понятным сообщением, пока статус не «утверждена» |
| План и брифы, упаковка, статусы | Прогон `briefs` и `plan` на утверждённой стратегии, смена статусов брифов | Каждый бриф содержит поля своего вида (в том числе упаковку: названия, два описания, теги, обложку; пометки по монтажу); в `plan.md` только «принятые»; нехватка принятых названа в выводе |
| Квота кончилась / сбой API | Кассета с ответом «квота исчерпана», затем повторный запуск | Прогресс в `run.json`; второй запуск идёт с того же места, число запросов к API не включает уже собранное |
| Повторы при сбое YouTube и Claude | Заглушки, падающие 3 раза; заменитель ИИ в режимах «ошибка», «пустой ключ», «нет баланса» | Ровно 3 повтора с растущей паузой, затем остановка с сообщением по-русски; собранные данные в кэше целы |
| ИИ вернул мусор | Заменитель ИИ отдаёт пустой или неразборчивый ответ | Понятное сообщение, ничего не записано в `virals.json`, `strategy.md` и брифы |
| Неполные данные | Кассета с пропущенными видео | В отчёте пометка «неполные данные» с числом пропущенных |
| Максимум и «позже» | План с принятыми брифами выше максимума; в следующем месяце возврат брифов «позже» | Программа не режет план сама и просит перенести лишнее; брифы «позже» доступны в новом запуске |
| Правка стратегии | Правка `strategy.md` руками и повторный `strategy` | Правка не потеряна без подтверждения; `plan` ждёт статуса «утверждена» |
| История и повторный запуск | Два запуска в одном месяце и запуск в следующем | Новая версия `v2` создана, прежняя цела; отклонённая тема не предлагается повторно |
| Файлы руками | Битая правка `strategy.md`, битая строка статуса в брифе, обрыв записи JSON | Сообщение по-русски с названием файла и места; файл не перезаписан |
| Нет ключа / неверный ключ | Запуск без `.env` | Понятное сообщение, как задать ключ; запросов 0 |
| Секреты не в репозитории | Поиск секретов (gitleaks, ставится в `make setup`) по файлам и истории git (репозиторий создаётся до первого коммита) + проверка `.gitignore` | Ключей нет; `.env` и папка данных игнорируются |
| Нет сети и денег | `make check` с запретом сокетов в тестах и пустыми ключами | 0 реальных обращений в счётчике `run.json`; `--real` по умолчанию выключен |
| Чистая установка по README | В чистой временной папке выполнить шаги README с фиктивным ключом | Первый запуск доходит до оценки квоты без правок кода |

> «Ошибок нет» — не доказательство. Доказательство — наблюдаемый результат: содержимое файла запуска, число запросов в журнале, текст сообщения.

**Настоящий прогон** (реальные YouTube API и Claude API) — отдельно от автопроверок: только вручную, командой `produce --real` после показа оценки квоты и стоимости и явного «да». ИИ сам настоящий прогон не запускает. Ручной чек-лист для человека после прогона: (1) в отчёте залёты правдоподобны; (2) эмоции и темы совпадают с тем, что видно в комментариях; (3) брифы можно взять в работу без переписывания структуры; (4) фактический расход квоты и денег близок к оценке. Фиксированный ИИ в автопроверках подтверждает только наличие и формат полей, а не качество ответов настоящей модели.

## Инструменты для ИИ

| Инструмент | Зачем |
|-----------|-------|
| pytest | Запуск всех проверок и сравнение результатов с ожидаемыми |
| pytest-recording (на VCR.py) | Запись и воспроизведение ответов YouTube без сети, ключ вырезается |
| gitleaks | Проверка, что в файлах и истории нет ключей |
| Мини-скиллы-обёртки | «прогони проверки» (`make check`), «сбрось тестовый канал» (`make reset`); «настоящий прогон» не обёртка, только по слову человека |

Браузерная автоматизация и MCP к базе не нужны: у программы нет экранов и базы, результат виден в файлах и выводе команд.

## Локальные заменители (при автоматических проверках)

| Компонент (из слоя 2) | Локальный заменитель | Зачем |
|-----------------------|----------------------|-------|
| YouTube Data API | Записанные ответы (кассеты) и заглушка сбоев | Без квоты, ключа и сети; воспроизводимо |
| Claude API (провайдер ИИ) | Фиксированный «провайдер ИИ» с заготовленными ответами и режимами сбоев | Бесплатно и предсказуемо; сам слой «провайдер» проверяется отдельно |
| Папка данных и `.env` | Временные папки на каждый тест | Не трогаем реальные данные канала и ключи |
