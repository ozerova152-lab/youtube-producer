**Где кончается бесплатное:** квота YouTube 10 000 единиц в день (поиск 100, остальное по 1); кончилась: прогресс сохраняется, продолжается завтра. Главный реальный предел — лимит подписки на агента: разбор комментариев и брифы расходуют его, поэтому шаги разбиты на части. Файлы кончаются при сотнях запусков.

**Хостинг / развёртывание:** продукт запускается на компьютере пользователя; страница-витрина публикуется через GitHub Pages (бесплатно); репозиторий на GitHub (публичный с 2026-10-30) · **Домен:** свой не нужен, адрес `https://ozerova152-lab.github.io/youtube-producer/` · подробности и решение — в разделе «Развёртывание» ниже.

## Развёртывание

> Решение принято 2026-10-29 (`/plan-deploy`, режим пересмотра: прежняя запись о GitHub Pages подтверждена и уточнена). Сам скилл ничего не настраивал.

| Что | Где живёт | Тариф и цена | Чем оплачивается |
|-----|-----------|--------------|------------------|
| Продукт (скрипт, сценарии, шаблоны) | Компьютер пользователя; исходники в репозитории GitHub | 0 ₽ | — |
| Страница-витрина (`site/`) | GitHub Pages, адрес `https://<аккаунт>.github.io/<репозиторий>/` | Free для публичного репозитория, 0 ₽ | — |
| Репозиторий | GitHub, станет публичным при публикации; лицензия MIT (выбрана человеком) | Free, 0 ₽ | — |
| База, файлы, фоновые задачи, почта, домен, модель ИИ | Не нужны: данные в файлах на компьютере пользователя, ИИ — подписка пользователя | 0 ₽ | — |

**Почему так.**
- Развёртывать нужно только одну статическую страницу без сервера и обязательного JavaScript, остальное работает локально (слой 2, «Компоненты»).
- Бюджет 0 ₽ и платное только с отдельного «да»: бесплатный вариант закрывает все требования, платный не нужен.
- Аудитория витрины в основном российская (ответ человека, 2026-10-29); репозиторий станет публичным (ответ человека), поэтому платный план GitHub и второй сервис не нужны.

**От чего отказались.**
- Приватный репозиторий с GitHub Pages: нужен платный план (по документации GitHub и обзорам 2026 года Pro или Team, порядка $4 в месяц); не нужен, раз репозиторий станет публичным.
- Cloudflare Pages как запасной хостинг: бесплатно принимает и приватные репозитории, но это второй сервис без пользы, пока GitHub доступен: кнопка «Скачать на GitHub» всё равно ведёт на GitHub, зеркало одной страницы распространение не спасёт.

**Известный риск.** С мая 2026 года у части российских провайдеров GitHub работает с перебоями (по сообщениям СМИ; прямых данных именно по `github.io` не найдено). Смягчение уже есть на самой витрине: адрес репозитория показан текстом, рядом фраза «Если GitHub не открывается, попробуйте позже».

**Когда пересматривать.**
- Страница или репозиторий недоступны у заметной части аудитории (жалобы читателей, замеры OONI или знакомых из России): тогда зеркало репозитория и страницы на втором хостинге.
- Появились форма, оплата, вход или серверная часть: это уже другой продукт, вопрос решается заново.
- GitHub изменил условия бесплатного Pages для публичных репозиториев.

**Настроить руками (чек-лист человека).** Скилл и `/deploy-audit` этого не делают:
1. Лицензия MIT уже выбрана и добавлена (`LICENSE`); перед открытием репозитория выполнить `make check` и `/security-review` (правило `AGENTS.md`). Затем GitHub → репозиторий → Settings → General → Danger Zone → Change repository visibility → Public.
2. Решить, как публиковать папку `site/`. Настройка Pages «Deploy from a branch» умеет публиковать только корень репозитория или папку `docs/` (по моим знаниям, в этой сессии не сверял; проверьте в Settings → Pages), а у нас страница лежит в `site/`, и `docs/` занята спекой. Поэтому нужен файл `.github/workflows/pages.yml` (GitHub Actions публикует `site/`): для публичного репозитория это бесплатно. Файла в проекте нет; его создание — отдельная задача, не часть этого решения.
3. Включить Pages: Settings → Pages → Source: «GitHub Actions».
4. Открыть `https://<аккаунт>.github.io/<репозиторий>/` с компьютера и телефона, проверить кнопку «Скачать на GitHub» и «Скопировать адрес»; при возможности открыть из российской сети.
5. Убрать из README пометку «заглушка до публикации» у адреса репозитория (сделано 2026-10-30: репозиторий публичный, витрина открывается по адресу выше).
6. Платных функций не включать (платный план GitHub, карта в аккаунте не нужны); стоп-кран расходов не требуется, потому что платить не за что.
7. Лимиты бесплатного Pages (порядка 1 ГБ на сайт и 100 ГБ трафика в месяц) я по памяти не сверял; страница весит до 1 МБ, запас большой, но сверьте на сайте GitHub.

## Схема данных (файлы вместо таблиц)

Папка данных канала (в `.gitignore`, по умолчанию `data/<канал>/`): в корне только `settings.yaml`, всё остальное лежит **внутри папки запуска** `runs/<месяц>_<сегмент>_v<N>/`. Новая версия запуска в том же месяце копирует кэш предыдущей, поэтому повторный запуск не тратит квоту заново; импорт кладёт данные в кэш текущего запуска. Пример настроек и образцы файлов лежат в репозитории (`examples/`).

| Сущность (файл) | Ключевые поля | Кто пишет |
|-----------------|--------------|-----------|
| Настройки (`settings.yaml`) | ниша, аудитория, сегменты, слова, конкуренты, мой канал, пороги, пределы | человек |
| Запуск (`run.json` в папке запуска) | месяц, сегмент, язык брифа, версия, этап, расход квоты, счётчик обращений, ожидает ли подтверждения оценка квоты, неполные данные | скрипт |
| Видео, Канал, Комментарий (`cache/*.json` в папке запуска) | статистика, недавние ролики, норма, тексты комментариев залётов | скрипт (сбор или импорт) |
| Залёт (`virals.json`), отчёт (`report.md`) в папке запуска | видео, просмотры, норма, вовлечённость | скрипт |
| Разбор (`analysis.md`) | темы и эмоции по залётам | агент по шаблону |
| Ниша, Кандидаты (`niche.md`, `candidates.md`) | темы, форматы, каналы, причина | агент по шаблону |
| Стратегия (`strategy.md`) | вводные, баланс форматов, частота, статус «черновик / утверждена» | агент, статус ставит человек |
| Бриф (`briefs/<id>.md`) | вид, статус (принят / отклонён / позже), структура вида, упаковка, образцы | агент, статус ставит человек |
| План (`plan.md`) | принятые брифы, месяц | агент по шаблону |

История запусков = папки `runs/`; повторный запуск в том же месяце создаёт новую версию только после слова человека.

| Сервис | Что делает | При сбое |
|--------|-----------|----------|
| YouTube Data API (скрипт) | Поиск видео, статистика каналов, комментарии залётов; платные по квоте вызовы идут только после подтверждения человека | 3 повтора с растущей паузой; квота кончилась: прогресс сохранён, продолжить завтра; нет или неверный ключ: понятное сообщение и подсказка про импорт |
| Агент пользователя | Исполняет сценарии, вызывает скрипт командами | Лимит подписки кончился: результаты уже в файлах, продолжить позже; проверка файлов красная: исправить и не идти дальше |

## Надёжность файлов

Скрипт пишет файлы через временный файл с переименованием. Файлы агента и ручные правки проверяет скрипт проверки: битый файл или ошибка формата дают сообщение по-русски с названием файла и места, ничего не перезаписывается.

## Секреты и безопасность

Ключ YouTube лежит только в локальном `.env`, не попадает в отчёты, `run.json` и логи (в `.gitignore`; в репозитории `.env.example` без значений). Файл `.env` создаёт команда `make add-key` (ввод скрыт, права только для владельца, значение не печатается и не логируется; запускает человек в обычном терминале, агент ключ не просит). Агент `.env` не читает: это правило в `AGENTS.md`, а в Claude Code дополнительно запрет в настройках прав (**только Claude Code**; в Cowork и Codex ключ держится лишь на инструкции, и README говорит это прямо). Комментарии и чужие тексты — данные, а не инструкции: агент не выполняет команды из них. Агенту не даются инструменты публикации. Мини-скиллы `/check` и `/reset` в `.claude/skills/` — тоже только Claude Code; те же команды записаны текстом в `AGENTS.md`.

## Открытые вопросы

- GitHub Pages на бесплатном тарифе работает только для публичного репозитория: витрина публикуется после того, как репозиторий станет публичным (до этого страница проверяется локально). Тариф не покупаем без отдельного «да».
- На странице нет ключей и реальных данных канала: пример результата берётся из `examples/demo/`.
